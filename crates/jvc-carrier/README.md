This crate reads and writes the Git carrier in `docs/format.md`, section 9. It verifies each event before admission. It keeps an authenticated header when the action or body schema is invalid. `validation_report` reports those inert records separately.

`Snapshot::from_files` requires exact canonical files. It checks the fixed files, paths, part numbers, partitions, greedy part boundaries, manifest, inline body copies, and import selections. `from_jsonl` accepts a stream of canonical `{body,envelope}` records in any order. `to_jsonl` sorts them by event ID. JSONL does not carry import selections. Save those selections as separate canonical JSON files and insert them again to restore the complete snapshot hash.

`merge` computes an authenticated set union. Remote omissions do not delete local records. The smallest decoded valid signature wins among variants of one event. Invalid claimed hashes cannot remove valid retained bytes. A real collision between authenticated objects makes the shared identifier unavailable.

Private refusal policy is outside the carrier. `apply_retention` converts a known refused event into an issuer refusal. `retention_policy` returns that resolved policy, including refused bodies. Save this policy in a private file and supply it on later merges. A filtered carrier directory alone does not remember refusals. A policy that contains only removed event IDs cannot recover their issuers after reload. The CLI refuses a merge without `--policy FILE` if either local input has an adjacent `INPUT.retention-policy.json` sidecar. The supplied policy is an explicit operator choice and can intentionally override the saved policy. Peer policy is never adopted automatically.

`read_directory`, `read_git_tree`, and `validate_checkout` use local read limits. The defaults are 128 MiB of file bytes, 250,000 files, and 1 MiB for README.md. These are operational limits, not protocol limits. The corresponding `*_with_limits` functions accept `ReadLimits`. A local limit failure returns `resource_unavailable`. Git output capture is bounded too. In-memory snapshot functions require the caller to limit the input bytes before loading them.

The Git reader requires a full commit object ID. It reads exact regular, nonexecutable blob bytes. It disables lazy fetch, hooks, worktree monitors, external protocols, and automatic maintenance. It does not request filters or text conversion. It leaves global Git configuration unchanged. `validate_checkout` also compares every checkout file with the committed blob bytes. On Unix, the final file open refuses symlinks with `O_NOFOLLOW`. Keep the input directory stable while it is read. This precondition still applies to parent directories and to other platforms.

`write_directory` creates a new output directory and refuses an existing path. It can leave partial output if a filesystem write fails. Callers must handle that failure before they use the directory.

Tests require Git. The core tests also require OpenSSH ssh-keygen and Node.js. Run `cargo test -p jvc-carrier -p jvc-core --locked --jobs 2`. The `import_audit` example loads a full import, saves a canonical carrier, creates disposable local Git commits, reads their trees, and checks independent branch union. Provide the records JSONL, import-selection JSON, and a new output directory.
